# Ship rewire's speed claim, not its scoreboard

rewire is ready to release as an **alpha**. It is not ready to publish numbers that put it ahead of Mem0, Zep or the other memory projects, and adding latency and token cost to the picture does not change that. It changes which claims rewire can make. Three efficiency claims hold up today. First, by default rewire makes **no LLM calls at ingest or at recall**; every extraction-based competitor pays one or more LLM calls per message pair or session. Second, local in-process retrieval takes **about 10–30 ms p50 on LoCoMo and PersonaMem, about 90 ms on LongMemEval_S and about 100–150 ms on BEAM 100K**, with no network hop. Third, memory context is **3–14× smaller than the full history** (99× at PersonaMem 1M). Three tempting claims fail. rewire is **not more token-efficient than the leading memory systems on long histories**: on LongMemEval_S it sends about 15k tokens of memory per question by a characters-divided-by-four estimate, against Zep's 4.4k median and Hindsight's 8.2k budget. Its **retrieval tail latency** on BEAM (p95 0.5–1.0 s) is worse than the managed services' 155–162 ms. And rewire has **never measured end-to-end answer latency**, so it has no figure to set against Mem0's 0.7–1.1 s or Zep's 2.6 s. Every J figure still comes from Claude Haiku answering and Claude Haiku judging: LoCoMo 93.0%, LongMemEval_S 83.6%, PersonaMem 32k 59.3%, BEAM 100K about 46% on 20 questions. Competitors' figures come from other models, other judges and mostly vendor self-reports. Worse, no full-dataset run pairs a J score with the latency and token profile of the configuration rewire actually ships. Before publishing, rewire needs a full-set re-run of the shipped default that logs J, tokenizer-counted tokens and direct-API end-to-end latency together, alongside a protocol-matched judge and a same-model full-context baseline. These runs are cheap. Without them, the numbers stay internal engineering measurements.

## How to read every number in this report

Most competitor figures here are **search-engine extracts of the primary page, not verified against the PDF**. The arXiv, mem0.ai and getzep.com pages could not be fetched directly in this session. Figures marked † come from extracts. Figures marked ‡ were cross-checked across several independent extracts and agreed, which is stronger than a single extract but still not a primary-source reading. Every vendor number is self-reported unless labelled 3P, meaning it was measured by a third party, often a competitor. All rewire figures come from the repository's own result files ([run.py](../experiments/eval/run.py); [results directory](../experiments/eval/results/)). Where a figure was recomputed from the per-question JSON rather than read from a report, it is marked "computed".

Five measurement differences decide whether two numbers can be compared. Each affects rewire directly.

**Retrieval-only versus end-to-end.** rewire's `retrieval_ms` times only the recall call, on an index that is already built, with any extra queries computed beforehand. It contains **no LLM time** ([run.py l.336–343, 600–608](../experiments/eval/run.py)). Mem0's 2025 "search" column, Zep's 2026 figures and Hindsight's recall figures are also retrieval-only. Mem0's "total", Mem0 v3's p50, Zep's 2025 2.58 s, EverMemOS's 2.46 s and Emergence's 5.65 s are end-to-end and include the answer model.

**Local versus managed cloud.** rewire runs in the same process, or as one CLI process, on a 4-vCPU container. Zep's 2025 latency explicitly includes the network round trip from a Boston laptop to Zep Cloud ([Zep paper](https://arxiv.org/html/2501.13956v1)). The 2026 vendor numbers do not say whether they include the network, the region or the concurrency. A local 20 ms against a cloud 100 ms therefore shows the deployment model, not a better algorithm. The fair comparison is rewire's p50 and p95 against theirs, with the deployment stated alongside.

**Estimated versus tokenizer-counted tokens.** rewire's `context_tokens` and `raw_tokens` are **characters divided by 4** ([run.py l.68](../experiments/eval/run.py)). Its "answer tokens in" figures are the real `usage.prompt_tokens` billed for the `claude -p` call, and that call adds a fixed **1,319-token** overhead measured with a one-word prompt ([rust-gated-expansion](../experiments/eval/results/2026-10-17-ab-rust-gated-expansion.md)). The billed prompt exceeds the chars/4 estimate by about 3.2k tokens on LoCoMo and 6.7k on LongMemEval. Once the 1,319-token overhead is removed, the implied undercount is **roughly 35–40%** (my inference from the repo's figures, not a direct tokenizer measurement). This inference checks out against an outside figure: rewire's chars/4 LoCoMo history of about 18.3k tokens, raised by 35–40%, lands near the **≈26k** tokens per conversation in the Mem0 paper‡ ([Mem0 paper](https://arxiv.org/html/2504.19413v1)). Competitors' "memory tokens" are probably tokenizer counts, but none of the extracts says which tokenizer.

**Mean versus median.** rewire reports **means** and p95s for tokens. Zep's 2026 page reports **medians** (4,408 and 5,760)†. rewire's token distributions are right-skewed (LongMemEval_S mean 15,060, p95 27,862), so its median sits below its mean. Comparing rewire's mean against Zep's median makes rewire look worse than it is.

**Memory context versus whole prompt.** Mem0's "1,764 tokens" is the memory sent per query, not the answer prompt. rewire's comparable figure is `context_tokens`, not its 7.7k–27k billed prompt, which also contains instructions, the question and the `claude -p` overhead.

The tables below grade each comparison. **No figure in this report earns an A**, meaning same metric, same model and same harness. **B** means the same quantity in a different deployment or with a different model: an order-of-magnitude comparison only. **C** means the quantity is nominally the same but its definition differs (mean vs median, chars/4 vs tokenizer, retrieval vs end-to-end). **D** means do not compare.

## rewire's own profile: fast, LLM-free retrieval with a token bill that grows with history

Read by itself, rewire's measured profile is coherent. The shipped default is configuration W: episodes mode, k=30, 10 excerpts, semantic search via WordLlama, and query expansion gated by rules. On the 190-question A/B suite its Python retrieval p50/p95 is **20/61 ms on LoCoMo, 88/259 ms on LongMemEval_S, 95–107/513–612 ms on BEAM 100K and 15–27/31–94 ms on PersonaMem 32k** ([embedding-rerank](../experiments/eval/results/2026-10-17-ab-embedding-rerank.md); computed from per-question rows). Measured with nothing else running, LoCoMo W is 28/89 ms and BEAM W 153/1,001 ms ([additive-graph](../experiments/eval/results/2026-10-19-ab-additive-graph.md); [episode-entity-graph](../experiments/eval/results/2026-10-19-ab-episode-entity-graph.md)). The Rust engine called as a CLI shows **14/57 ms (LoCoMo), 156/299 ms (LongMemEval_S), 73/404 ms (BEAM) and 10/35 ms (PersonaMem)** after subtracting a fixed 96 ms for process start and loading the WordLlama model. Rust and Python reach the same verdict on all 190 questions ([rust-gated-expansion](../experiments/eval/results/2026-10-17-ab-rust-gated-expansion.md)). On long histories the Rust engine is not faster, which contradicts the README's blanket "recall ~20 ms" ([README](../README.md)). That claim holds only for small brains.

Several latency figures in the repo should not be quoted. Recall times from "end-to-end" runs were measured while four answer calls ran in parallel. Examples are LoCoMo W at 102/292 ms and LongMemEval W at 321/1,034 ms, and the repo itself calls these noisy ([embedding-rerank](../experiments/eval/results/2026-10-17-ab-embedding-rerank.md)). The 2026-10-16 LongMemEval arms A and B (235 ms and 1,119 ms p50) used recall-time sentence-vector condensing, which was later dropped "for latency with the same evidence" ([personamem-haiku55](../experiments/eval/results/2026-10-17-personamem-haiku55.md)). The LoCoMo full-mode retrieval-only p50 of 288 ms includes building the index on first use ([full-graph-ablation](../experiments/eval/results/2026-10-20-locomo-full-graph-ablation.md)). The cleanest small-brain number comes from the synthetic benchmark: a warm MCP server recalls in **6 / 8 / 34 ms at 500 / 2,000 / 10,000 nodes** ([perf README](../experiments/perf/README.md)). No one has measured a warm Rust MCP server on benchmark-sized brains.

Tokens tell a less flattering story. W sends a mean of **2,769 tokens of memory on LoCoMo, 15,060 on LongMemEval_S, 17,945 on BEAM 100K and 11,762 on PersonaMem 32k** (chars/4). The p95s are 5,294, 27,862, 48,547 and 18,182. The billed answer prompts are 7,716, 21,911, 26,818 and 15,886 ([embedding-rerank](../experiments/eval/results/2026-10-17-ab-embedding-rerank.md); [rust-gated-expansion](../experiments/eval/results/2026-10-17-ab-rust-gated-expansion.md)). Against the full history, also chars/4, that is **6.6× compression on LoCoMo (≈18.2k), 8.1× on LongMemEval_S (≈122.7k), 8.4× on BEAM 100K (≈151k) and only 3.1× on PersonaMem 32k (≈36k)**. Because the context budget is fixed at about 11–12k, PersonaMem compression rises to **14.5× at 128k and 99.4× at 1M**, while accuracy falls only from 59.3% to 55.7% and then 51.4% ([personamem-haiku55](../experiments/eval/results/2026-10-17-personamem-haiku55.md)). The design decision behind these numbers is that rewire sends whole turns and excerpts, not distilled facts. That is why its context grows with history length while fact-extraction systems stay at 2–7k.

Retrieval-side LLM spend is small when averaged, and large on the questions that trigger it. Rule-gated expansion fires on **0–50% of questions**: 13 of 40 on LoCoMo, 30 of 60 on LongMemEval, 6 of 20 on BEAM and 0 of 70 on PersonaMem. Each expanded question costs about **250–262 prompt + 62–76 completion tokens through the API**, or about 1,570–1,580 prompt tokens once the `claude -p` overhead is included. Averaged over all 190 questions that is 67 + 18 tokens. Each expansion is **one LLM call taking p50 ≈4.9 s and p95 ≈6.0–6.3 s through `claude -p`**. The model-gated variants (C3, C4) call the LLM on every question, at about 390 + 151 tokens and 5.2–5.4 s p50 ([rust-gated-expansion](../experiments/eval/results/2026-10-17-ab-rust-gated-expansion.md); computed from the LLM caches). None of the `retrieval_ms` figures includes this call. A user whose question triggers expansion therefore waits about 5 s more than the "20 ms recall" suggests. Expansion latency through the direct API has never been measured. When an agent uses rewire over MCP, the agent writes the extra queries itself and rewire makes no LLM call ([extra-queries](../experiments/eval/results/2026-10-15-locomo-ab-extra-queries.md)).

Ingest splits sharply by mode. **Episodes mode, the default, makes zero LLM calls.** A LoCoMo conversation's brain takes **1.1 MB on disk**, of which the index (`.index`, holding full-text search and WordLlama vectors) is 612 KB. A LongMemEval_S question's brain takes about 2.8–3.1 MB, and a BEAM 100K brain 3.0–4.6 MB (measured with `du`). **Full mode**, which produced the 93.0% LoCoMo headline, consolidates every session with about two LLM calls. That comes to roughly **544 calls for LoCoMo's 272 sessions**, a measured **p50 of 37–42 s per session (p95 55.5 s)** and **about 2.9 hours of serial wall time**. The resulting brain is 6.6 MB per conversation ([locomo-haiku-full](../experiments/eval/results/2026-10-15-locomo-haiku-full.md); [full-graph-ablation](../experiments/eval/results/2026-10-20-locomo-full-graph-ablation.md)). **Ingest tokens were never logged.** No `ingest` stage appears in any LLM cache that was checked, so full mode's token bill can only be estimated. The one dollar figure on record is PersonaMem: 869 answers would have cost **$2.89 at API prices** (about $0.003 per answer), though the run was billed through a subscription ([personamem-haiku55](../experiments/eval/results/2026-10-17-personamem-haiku55.md)).

## No benchmark run pairs a J score with the shipped configuration's cost

This is the central finding of the latency and token review. A publishable claim needs J, tokens and latency **from the same run of the same configuration**, and rewire does not have that for the configuration it ships. The LoCoMo 93.0% came from full mode (k=30, 20 excerpts, 5,013 tokens, 9/20 ms), not from the LLM-free default. The LongMemEval_S 83.6% came from arm A, whose recall-time condensing was later removed for being slow (235/651 ms). The PersonaMem 59.3% used the same since-dropped recall ([personamem-haiku55](../experiments/eval/results/2026-10-17-personamem-haiku55.md)). The current default W has only been measured on 40–70-question samples per benchmark. Two consistent triples do exist. One is LongMemEval_S baseline: **78.4% J, 8,842 tokens, 21/56 ms**, keyword only, n=500 ([longmemeval-haiku55-ep10](../experiments/eval/results/2026-10-16-longmemeval-haiku55-ep10.md)). The other is LoCoMo full mode: **93.0%, 5,013 tokens, 9/20 ms**, but with about 544 ingest LLM calls. Neither is what a new user installs.

The tables below put accuracy, tokens, latency and ingest in one view for each benchmark. J figures carry their answer model and judge, because the earlier analysis found that **model and judge choice explain more of the published spread than memory design does**. A cross-system J comparison is only valid when answerer, judge, judge prompt, question set and retrieval budget all match. None of the rows below matches rewire on all five.

Corrected for the chars/4 undercount, it is probably 3.5–4k tokens, still in the middle of the pack. Retrieval at 20–28 ms p50 is several times faster than any cloud figure, but that is a **grade B comparison: local without network against managed with network**. It shows rewire adds negligible latency. It does not show a better algorithm.

Ingest is where rewire's default stands apart. Mem0 makes one or two LLM calls per message pair. Hindsight needed 581 model calls for LoCoMo. rewire's episodes mode needs none. Its full mode (544 calls) costs about the same number of calls as Hindsight, but at 2.9 hours serial it is much slower than Hindsight's 772.7 s. The comparison is grade B at best, since the Hindsight run used local vLLM and may have run in parallel.

One more figure puts rewire's answer-side bill in context. Answering all 1,540 questions at W's 7.7k billed prompt comes to roughly **11.9M input tokens**, and full mode's 11.1k comes to about 17.1M (my arithmetic). MemMachine reports Mem0 at **19.21M** input tokens and itself at 4.20M on LoCoMo with gpt-4.1-mini† ([MemMachine](https://arxiv.org/pdf/2604.04853)). It is not clear whether those totals include ingest. rewire's figures include about 2M tokens of `claude -p` overhead.

Last, the latency argument for memory over full context is weaker than the 2025 papers suggest. With a 2026 model, **full context answered LoCoMo in 1.78 s median, faster than Mem0 (2.19 s) or EverMemOS (2.46 s)**†, because 26k tokens is short ([User as Code](https://arxiv.org/html/2606.16707v1)). rewire needs its own same-model full-context run before claiming any latency benefit on LoCoMo.

This is the benchmark where the token story turns against rewire. ## The field's cost numbers are as unreliable as its accuracy numbers

The earlier accuracy analysis found that self-reported J scores collapse when a shared harness reruns them: Zep 94.7 fell to 63.8, Backboard 90.1 to 22.4 ([Tenconic LEADERBOARD](https://github.com/tenconic-ai/tenconic-memory-evaluation/blob/main/LEADERBOARD.md)). Latency behaves the same way. **Mem0's own paper puts Mem0's total p50 at 0.708 s‡; the MemOS team measured 4.906 s†** ([MemOS PDF](https://statics.memtensor.com.cn/files/MemOS_0707.pdf)), a 7× gap for one system. Zep and Mem0 disagree about whether Zep was queried serially and set up correctly ([Zep rebuttal](https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)†). Zep's move from "2.58 s" (2025) to "104 ms" (2026) changes the metric, from end-to-end to retrieval-only, and is not a 25× speed-up. Token figures drift too. EverMemOS's per-question tokens appear as 2,298, about 2.8k, and 6,045–6,669 in different places, and an audit cuts its claimed 89% reduction against full context to 67% ([locomo-audit](https://github.com/dial481/locomo-audit)). Mastra's "10× cheaper" headline rests on generic prompt-cache discounts, not a measured bill ([VentureBeat](https://venturebeat.com/ai/observational-memory-cuts-ai-agent-costs-10x-and-outscores-rag-on-long)†). Mem0 v3 raised context from about 1.8k to about 7k tokens to lift LoCoMo from 66.9 to 92.5. Its "token efficiency" is measured against full context, not against its own earlier version.

Two consequences follow for rewire. First, there is **no neutral harness that publishes latency and tokens for Zep, Hindsight, Supermemory, Letta, Cognee and Mem0 together**. RealMem is the closest: it measured add times of 8.7–26.9 s and retrieval of 0.013–1.261 s for Mem0, A-Mem, MemoryOS and a graph memory† ([RealMem](https://arxiv.org/pdf/2601.06966)). So any "rewire vs X" cost table built from published numbers is a collage of incompatible methods. Second, rewire's best-supported advantage is ingest, which is also the line most vendors leave unpublished. Every independent table agrees that **writes cost far more than reads**: seconds per add against milliseconds per read. An ingest path with no LLM calls deletes that line entirely. That claim needs no competitor's cooperation to verify. It needs only rewire's own call logs, which already show zero LLM calls in episodes mode.

The steelman against rewire's efficiency claim is the cost model in "Beyond the Context Window". Fact-extraction memory beats long context on cost only after about 9–13 turns, and only once 90% prompt-cache discounts are counted from turn 2† ([arXiv 2603.04814](https://arxiv.org/abs/2603.04814)). rewire is not a fact store. Its retrieved context changes with every query, so it cannot reuse a cached prefix the way Mastra's append-only log can. Whether rewire is cheaper per query than cached full context on LoCoMo-sized histories is **an open question**, and it needs measuring rather than assuming.

## Conclusion

Adding latency and tokens sharpens what rewire is, but its release status stays the same: an alpha with no comparative scoreboard. rewire is not a cheaper Mem0 or a faster Zep. It is a **zero-LLM-ingest, local-first** memory that buys millisecond retrieval and portability by sending more raw text to the answer model than fact-extraction systems do. That trade wins on write cost and privacy, ties on read latency, and loses on tokens per query once histories pass about 100k tokens. The honest pitch is "no extraction bill, no server, retrieval in tens of milliseconds, about 11–15k tokens of context". It is not "beats X on LongMemEval".

The deeper implication is that rewire's evaluation harness is already better than most published ones. It logs per-question tokens, latency and expansion calls; it caches answers; and it re-judges from the cache. What is missing is discipline about which configuration it measures and how it counts tokens. One full-set run of the shipped default, counted with a real tokenizer and timed through the direct API, would make rewire one of the few memory projects whose accuracy, latency and cost all come from the same run. That alone would set it apart in this field.
