# Ship rewire as alpha, hold the scoreboard

rewire is ready to hand to other people as an **alpha**. It is not ready to publish benchmark scores that claim it beats other memory projects, because **none of its J scores can be compared like for like with any published competitor number**. On the engineering side the basics are done. It has a Rust binary and a Python reference engine that produce identical recall, CI that runs both, 71 Python and 66 Rust tests passing, an MCP server, and an explicit threat model. It still lacks registry packages and the real-user validations it set for itself (E1–E4). On accuracy, rewire's best numbers are **LoCoMo 93.0% J** (all 1,540 questions), **LongMemEval_S 83.6% with the default configuration and 85.6% with LLM query expansion** (all 500), **PersonaMem 32k 59.3%** (all 589) and **BEAM 100K about 46% on only 20 questions**. Every J came from a Claude Haiku answerer judged by a Claude Haiku judge. Competitors used gpt-4o-mini, GPT-4o, GPT-4.1, GPT-5.4, Gemini 3 or GPT-OSS-120B, so "better than Mem0 or Zep" is neither proven nor disproven. In practice LoCoMo is saturated: 93.0% sits at the roughly 93.6% ceiling set by a wrong answer key, and plain full-context with gpt-4.1-mini reaches 92.6%. On LongMemEval, rewire trails the 2026 vendor claims of 91–95%. PersonaMem is the closest thing to a fair comparison, and there rewire ties the MemOS, Memobase and Zep figures within noise. BEAM has too few questions to rank anyone. Before publishing scores, rewire needs four things: a run with a protocol-matched answerer and judge, a full-context baseline run through its own harness, error bars, and per-question outputs others can re-judge. These are cheap to produce, because the runner already caches answers and re-judges from the cache.

## The software clears an alpha bar; the validation plan does not

rewire's engineering readiness is stronger than its evaluation story. Install works from git with `cargo install --git …` or `pipx install git+…`. The Rust binary is about 9 MB, bundles SQLite, and primes and recalls in about 20 ms. The same install wires into Claude Code and Codex as an MCP server and as hooks ([README.md](../README.md)). In this session, `python -m unittest discover -s tests` ran **71 tests, all passing**, and `cargo test --offline` passed **66 of 66**. CI runs unittest on Python 3.11 and 3.13 plus `cargo test --locked` and `clippy -D warnings` ([ci.yml](../.github/workflows/ci.yml)). The parity contract has been checked: node files are byte-identical, recall matches on 304/304 LoCoMo questions, and the Rust and Python engines scored the same 72.2% on a 190-question end-to-end suite ([recall_parity.py](../experiments/conformance/recall_parity.py); [ab-rust-gated-expansion](../experiments/eval/results/2026-10-17-ab-rust-gated-expansion.md)). One caveat: most later A/B runs used only the Python engine.

The security design covers the threat the field now treats as standard. MINJA showed that an attacker can plant records in an agent's memory through queries alone, with no direct write access ([arXiv 2503.03704](https://arxiv.org/html/2503.03704v2)). rewire rescans stored notes for secrets and injection every time they are displayed, fences recalled text in `<rewire-memory>`, never turns tool output into a rule automatically, and can undo a session's consolidation ([security.rs](../rust/src/security.rs); [mvp-spec §9](../docs/design/mvp-spec.md)). Its own design review scores security 8.5/10 but notes the mitigations are **"not yet tested against real attacks"** ([design-review §6](../docs/design/design-review.md)).

The gaps are in packaging and validation. There is **no PyPI or crates.io release**, and the versions disagree: Python is 0.1.0, Rust is 0.2.0 ([pyproject.toml](../pyproject.toml); [Cargo.toml](../rust/Cargo.toml)). The project's own definition of v0.1 is milestone M5, "E4 passes". E4 calls for two weeks of dogfooding with at least a 40% snapshot hit rate. E1 calls for consolidation precision of at least 0.85 on 20 real transcripts, and only one session has been checked. Neither has been done ([iterations.md](../docs/iterations.md); [mvp-spec §10–11](../docs/design/mvp-spec.md)). Sync across multiple devices is "format ready, not yet enabled". Recall with LLM query expansion takes 1.1 s, and the repo itself says "latency regressed and needs work before shipping" ([longmemeval-improvements](../experiments/eval/results/2026-10-16-longmemeval-improvements.md)). The README also still uses Indonesian example queries, which conflicts with the English-only rule for the repository. The honest label for a release today is "alpha for early adopters".

## Model and judge choice, not memory design, explains most of the published spread

Every cross-project comparison comes back to one fact: on these benchmarks, **the answer model and judge move scores as much as the memory system does**. On LongMemEval_S, Zep scores 63.8% with gpt-4o-mini and 71.2% with GPT-4o ([Zep paper](https://arxiv.org/html/2501.13956v1), search extract). Mastra's Observational Memory ranges from 84.2% with gpt-4o to 94.9% with gpt-5-mini (search extract; [Mastra](https://mastra.ai/research/observational-memory)). Hindsight ranges from 83.6% with GPT-OSS-20B to 91.4% with Gemini-3 ([hindsight-benchmarks](https://github.com/vectorize-io/hindsight-benchmarks), fetched). Mem0 shows the extreme case: 94.4% when Mem0 ran it versus **49.0% in a third-party run**, a gap attributed to the answer and judge prompts ([levh issue #340](https://github.com/ali-ulu/levh/issues/340)). MemDelta found that the choice of answer model can flip the sign of RAG-versus-full-context conclusions. Full context won by 14 points on Gemini Flash, and retrieval won by 31 points on Sonnet ([MemDelta](https://arxiv.org/pdf/2606.29914), search extract).

Judges add their own bias. LLM judges are lenient. In one study a judge credited deterministically wrong answers on 5.4% of items and rejected correct ones on only 1.0%, inflating accuracy by about 5 points ([Memory-R2](https://arxiv.org/pdf/2605.21768), search extract). The Mem0 judge prompt, which rewire also uses, tells the judge to be generous. When Penfield Labs ran a similar judge, it accepted **62.8% of vague but on-topic wrong answers** ([locomo-audit](https://github.com/dial481/locomo-audit), fetched). Judges also prefer text that reads as familiar to them, which favours answers from the judge's own model family ([arXiv 2410.21819](https://arxiv.org/html/2410.21819v1)). On an expert-rubric task outside memory, Claude Haiku 4.5 agreed with experts less well (κ=0.535) than o4-mini or GPT-4.1 did ([PRBench](https://arxiv.org/pdf/2511.11562), search extract). This bears directly on rewire. Its LoCoMo headline has **Haiku 5.5 judging Haiku 5.5**. Its only cross-check is Haiku 4.5, also an Anthropic model, which agreed on 98.5% of answers and scored 93.6% ([locomo-haiku-full](../experiments/eval/results/2026-10-15-locomo-haiku-full.md)).

The consequence is a strict rule. **A score is comparable only when it shares the answer model, judge model, judge prompt, question set and retrieval budget.** None of rewire's published scores meets that rule against any competitor. The table below grades every comparison a reader might be tempted to make.

| Benchmark | rewire setup | Nearest published comparison | Same answerer? | Same judge? | Verdict |
|---|---|---|---|---|---|
| LoCoMo | Haiku 5.5 answers, Haiku 5.5 judge, Mem0 judge prompt, cats 1–4, n=1,540 | Mem0-paper era: gpt-4o-mini / gpt-4o-mini | No (rewire's is much stronger) | No | Not comparable; would flatter rewire |
| LoCoMo | same | OmniMemEval rerun: gpt-4.1-mini / gpt-4o-mini | No | No | Not comparable; closest in model strength |
| LoCoMo | same | Vendor self-reports 89–94.7 (GPT-5.4, Gemini-3, GPT-4.1 judges) | No | No | Not comparable; same strength band only |
| LongMemEval_S | Haiku 5.5 answers, Haiku 4.5 judge, official prompts, n=500 | GPT-4o rows (Zep 71.2, Supermemory 81.6, Mastra 84.2, Emergence 86) with GPT-4o judge | No | Prompt yes, model no | Not comparable |
| PersonaMem 32k | Haiku 5.5, 4-option multiple choice, n=589 | MemOS's own table (Mem0, Zep, Memobase, MemOS) | Unknown, likely no | No judge needed | Partly comparable: metric and split match, answerer differs |
| BEAM 100K | Haiku 5.5, Haiku 4.5 rubric judge, n=20 | Hindsight, Honcho, Cognee, LIGHT paper | No | No | Not comparable; sample too small even internally |

## LoCoMo: 93.0% hits the answer-key ceiling, so it cannot rank rewire

rewire's full LoCoMo run on 2026-10-15 scored **93.0% J** on all 1,540 category 1–4 questions. By category: single-hop 95.8%, temporal 94.1%, multi-hop 92.2%, open-domain 66.7%. The run averaged about 5k tokens of context and 9/20 ms retrieval at p50/p95 ([locomo-haiku-full](../experiments/eval/results/2026-10-15-locomo-haiku-full.md)). It used `--mode full`, which spends about two LLM calls per session on consolidation. That is **not the LLM-free default** rewire advertises, so the headline must say which mode produced it. The run also predates pinning the recall clock, so its contexts cannot be reproduced exactly ([evaluation.md §6](../docs/evaluation.md)).

The audited answer key caps this number. Penfield Labs found **99 of the 1,540 gold answers (6.4%) are wrong**, which puts the attainable overall score at about **93.57%**, with 95.72% for single-hop and 90.07% for multi-hop ([locomo-audit](https://github.com/dial481/locomo-audit), fetched). rewire's 95.8% single-hop and 92.2% multi-hop both sit **above those ceilings**. That is the same pattern the audit used against EverMemOS's 95.96/91.37. It means the judge is crediting some answers that disagree with the key, or the key is being matched some other way. rewire's own error analysis agrees. It found that lenient judging of list answers inflates J by about 2.5 points, and that **strict J is 89.4%** ([haiku-full-recommendations](../experiments/eval/results/2026-10-15-locomo-haiku-full-recommendations.md)). If rewire publishes LoCoMo at all, the strict 89.4% and the errata-adjusted figures should appear next to 93.0%.

The published landscape splits into three groups that should never share one axis. **Group (a)** is the 2025 Mem0-paper era, with gpt-4o-mini as both answerer and judge. Mem0 scored 66.88 and Mem0-graph 68.44 ([Memobase README copying the Mem0 paper](https://github.com/memodb-io/memobase/blob/main/docs/experiments/locomo-benchmark/README.md), fetched). Full context scored 72.90 and A-Mem 48.38 ([Mem0 paper](https://arxiv.org/abs/2504.19413), search extract). LangMem scored 58.10. Zep scored anywhere from 58.44 to 75.14 depending on who did the arithmetic ([zep-papers issue #5](https://github.com/getzep/zep-papers/issues/5), fetched). Memobase scored 75.78, and Letta's filesystem agent 74.0 ([Letta](https://www.letta.com/blog/benchmarking-ai-agent-memory/), search extract). **Group (b)** is vendor self-reports from 2025–26 at 89–94.7: Zep/Graphiti 94.7 with GPT-5.4 ([Graphiti page](https://www.getzep.com/platform/graphiti/), search extract), EverMemOS 92.3–93.05, Mem0 v3 92.5 with models not disclosed, Hindsight 89.61 with Gemini-3 and a GPT-OSS-120B judge (fetched), plus Backboard, ByteRover and MemMachine, all search extracts. **Group (c)** is the only shared-harness reproduction, the OmniMemEval snapshot of October 2026. It used a gpt-4.1-mini answerer and a gpt-4o-mini judge and scored MemOS 88.83, Cognee 83.48, Hindsight 81.99, Mem0 77.68, Letta 77.12, Supermemory 73.53 and **Zep 63.83** ([Tenconic LEADERBOARD](https://github.com/tenconic-ai/tenconic-memory-evaluation/blob/main/LEADERBOARD.md), fetched). The gaps between self-reports and reruns are large: Zep 94.7 vs 63.8, Backboard 90.1 vs 22.4, EverMemOS 93 vs 38–83. They are the clearest evidence that self-reported numbers do not rank systems.

rewire's 93.0% belongs with group (b): a strong answer model, judging configured by the authors, one run. Within that band nothing separates anyone, because every entry presses against a ceiling that a key-agnostic judge can exceed. The most damaging comparison for every memory vendor is **full context with gpt-4.1-mini and a chain-of-thought prompt, which scores 92.62** ([locomo-audit](https://github.com/dial481/locomo-audit), fetched). rewire has never run a full-context baseline with Haiku 5.5. Without one, a reader cannot tell whether rewire adds anything over pasting the whole conversation into the prompt. The obvious reply is that rewire answers from about 5k tokens instead of about 26k ([Mem0 paper](https://arxiv.org/pdf/2504.19413), search extract). That efficiency claim is real and defensible, but it is a different claim from "higher J". Even the vendors discount LoCoMo: Hindsight's own repo says it does "not consider this benchmark to be a reliable indicator of memory system quality" ([hindsight-benchmarks](https://github.com/vectorize-io/hindsight-benchmarks), fetched).

## LongMemEval: 83.6% by default trails the 2026 claims, but the gap is uninterpretable

LongMemEval_S is the more informative benchmark: histories run to about 115k tokens, and there are knowledge-update, temporal and abstention questions. rewire ran all 500 questions with the **official answer template and official per-type judge prompt**, but with a Haiku 4.5 judge instead of the official GPT-4o. It scored **78.4%** at baseline (BM25 only), **83.6%** with arm A (semantic search plus query-aware condensing, no LLM at recall), and **85.6%** with arm B, which adds Haiku query expansion at every recall ([longmemeval-improvements](../experiments/eval/results/2026-10-16-longmemeval-improvements.md)). With n=500, the +5.2 and +7.2 gains exceed the measured judge noise of ±1–3 points. A→B (+2.0) does not clearly exceed it. Each figure comes from a single run. Arm B also costs **1.1 s of recall latency** and about 27k prompt tokens, so the shippable headline is **83.6%**, not 85.6%. The weak spots are clear: single-session-preference 43.3% and multi-session 65.4% at baseline ([longmemeval-haiku55-ep10](../experiments/eval/results/2026-10-16-longmemeval-haiku55-ep10.md)).

Against published numbers, rewire sits in the middle of the field and below the newest claims. The paper's own reference points are full-context GPT-4o at **60.6%** and oracle GPT-4o (evidence sessions only) at **87.0%** ([arXiv 2410.10813](https://arxiv.org/html/2410.10813), search extract). Several systems used GPT-4o as answerer, and their scores were all produced with GPT-4o judges: Zep 71.2%, Supermemory 81.6%, Mastra 84.2% and Emergence 86.0%. Supermemory's came from the fetched hindsight-benchmarks table; the others are search extracts. Hindsight's open-model rows are 83.6% (GPT-OSS-20B) and 89.0% (GPT-OSS-120B), with a GPT-OSS-120B judge (fetched). The 2026 self-reports reach 91.4% (Hindsight with Gemini-3), 94.4% (Mem0 managed platform, which its own docs give as 93.4%), 94.87% (Mastra with gpt-5-mini), and 95.4–95.6% (OMEGA, Agent Zero). All are search extracts, and none has been independently reproduced. The peer-reviewed systems that are probably closest to rewire's protocol land lower: TiMem 76.88 ± 0.30 with gpt-4o-mini and 78.96 ± 0.26 with GPT-4o ([TiMem](https://arxiv.org/pdf/2601.02845), search extract), MemOS 77.8% and EverMemOS 83.0% ([ACL 2026](https://aclanthology.org/2026.acl-long.2125.pdf), search extract).

None of these pairs is apples to apples. The models are part of the problem. Haiku 5.5 is a newer model than GPT-4o, so beating GPT-4o-answered rows says little, and losing to GPT-5-class rows says little too. The judge is the other part: the official GPT-4o judge was validated at 90% or better agreement with humans, and Haiku 4.5 was not validated on this task. The fair statement is that **rewire's default configuration lands in the same 80–86% band as the GPT-4o-answered systems, with no LLM calls at ingest or recall**. That cost profile is genuinely unusual. It does not say rewire is better.

## PersonaMem is a statistical tie, and BEAM cannot be scored yet

PersonaMem v1 is four-option multiple choice, so it needs **no LLM judge**, and that removes the largest source of incomparability. rewire scored **59.3% on all 589 questions of the 32k split**, 55.7% at 128k and 51.4% at 1M. The last two were sampled at 140 questions each, with about ±8 points of error ([personamem-haiku55](../experiments/eval/results/2026-10-17-personamem-haiku55.md)). The MemOS team's table on the same metric reports Mem0 43.12, Zep 57.83, Memobase 58.89 and MemOS 61.17 ([MemTensor/MemOS_eval_result](https://huggingface.co/datasets/MemTensor/MemOS_eval_result)). memind self-reports 67.91 ([memind](https://github.com/openmemind/memind)). The 32k overall carries about **±4 points** of sampling error, and the repo measured a further ±4–6 points from answer sampling alone. So rewire is statistically indistinguishable from Zep, Memobase and MemOS, ahead of the MemOS-run Mem0 figure, and behind memind. The comparison is only partly fair. The answer model behind the MemOS table was not confirmed, and the numbers are contested: an independent re-run (BMAM, Table 14) gives **Mem0 53.9 and MemOS 34.0** ([BMAM](https://arxiv.org/pdf/2601.20465), search extract). rewire's weakest question type, `suggest_new_ideas` at 20–26%, is also below memind's 38.7% on the same type. For reference, the paper's frontier models reach about 52% at 128k ([PersonaMem](https://github.com/bowen-upenn/PersonaMem), fetched), and GPT-4o with the full 32k context reaches 39.2% ([PersonaVLM](https://arxiv.org/pdf/2604.13074), search extract). Chance is 25%.

BEAM is the benchmark vendors now treat as the one that cannot be gamed by stuffing the context, and it is where rewire is least ready. rewire has only run **20 questions at the 100K tier**, two per ability. Across three replicates the mean was **45.8%**, with single runs ranging from 39% to 54% ([replicated-ab](../experiments/eval/results/2026-10-20-replicated-ab.md)). It has never run 500K, 1M or 10M end to end, and it does not compute Kendall τ for event ordering, so its BEAM score cannot follow the official protocol yet ([evaluation.md §2, §10](../docs/evaluation.md)). At n=20 the error bar is about ±20 points. Published 100K figures include the paper's LIGHT at 0.358 with Llama-4-Maverick, quoted second-hand ([Scriptorium](https://github.com/Qi202/Scriptorium/blob/main/docs/experiments/protocols/unified_evaluation_protocol.md)). Honcho reports 63.0 ([honcho.dev](https://honcho.dev/evals/)), Hindsight 73.4 with a Llama-4-Maverick judge ([Hindsight blog](https://hindsight.vectorize.io/blog/2026/04/02/beam-sota)), and Cognee 0.79 ([Cognee](https://www.cognee.ai/blog/deep-dives/benchmarking-cognee-on-beam)). The vendor figures are self-reported, and most came via search snippets. Vendors also score BEAM differently. Mem0 judges each nugget with gpt-5 and rounds partial credit to 0, 0.5 or 1, which one analysis calls "systematically more lenient than official" ([Scriptorium](https://github.com/Qi202/Scriptorium/blob/main/docs/experiments/protocols/unified_evaluation_protocol.md)). Mem0 also reports both an average score (64.1 at 1M) and a pass rate (70.1%) ([Mem0](https://mem0.ai/library/agent-memory/how-to-read-memory-benchmarks)). On the evidence available, rewire is above the 2025 paper baseline and below the 2026 vendor claims. That conclusion carries no statistical weight.

## Six fixes before any score leaves the repo

rewire's own replicated experiments already show the discipline a public claim needs. Across three replicates of the 190-question suite, **no tested change beat the baseline**. A "significant" +3.9 on LongMemEval turned out to be a false positive. The fact graph added **0.0 points** on LoCoMo (95% CI −4.2 to +4.6) ([replicated-ab](../experiments/eval/results/2026-10-20-replicated-ab.md); [full-graph-ablation](../experiments/eval/results/2026-10-20-locomo-full-graph-ablation.md)). The full-dataset numbers, however, come from single, unreplicated runs, and every one of them used the Claude-family judges described above. The field's history shows what happens otherwise. MemPalace's "100% on LongMemEval" turned out to be retrieval recall@5 after fixing three known failing questions. It was revised to 96.6% after public criticism ([Hackernoon](https://hackernoon.com/resident-evil-star-milla-jovovich-shipped-an-ai-memory-system-devs-shredded-its-benchmarks); [arXiv 2604.21284](https://arxiv.org/pdf/2604.21284)). In the Mem0–Zep dispute, each side accused the other of misconfiguring its system and of arithmetic errors, and the issue closed without agreement ([issue #5](https://github.com/getzep/zep-papers/issues/5)). The fixes below are ordered by how much credibility each buys per dollar.

| # | Action | Why | Cost |
|---|---|---|---|
| 1 | Re-run LoCoMo with gpt-4o-mini as answerer and judge (Mem0 protocol), and LongMemEval_S with a GPT-4o judge on the existing answers | Gives the only protocol-matched numbers. The runner re-judges from cache ("only the judge is paid for") | ≈$1.60–2.30 for a full gpt-4o-mini LoCoMo run, per [evaluation.md §7](../docs/evaluation.md) |
| 2 | Run a full-context baseline with the same answerer and judge on both benchmarks | Answers "does memory beat pasting the history in?", the question that sank many LoCoMo claims | One extra arm |
| 3 | Report a 95% CI per score, replicate full runs at least 3×, use paired bootstrap or McNemar for every comparison, and label n<100 results "directional" | Single runs vary by ±3 points on LoCoMo, and n=20 BEAM is about ±20 points | Compute only |
| 4 | Publish per-question JSONL, prompts, dataset versions and commit hash, plus a one-command reproduction | Lets others re-judge. This is the norm set by Supermemory MemoryBench and Hindsight | Commit the outputs currently kept in the scratchpad |
| 5 | Headline only the default configuration (episodes mode, no LLM at recall), and label full mode and query expansion separately; report strict and errata-adjusted LoCoMo next to official J | Avoids the "benchmarked config differs from shipped config" overclaim | Editing only |
| 6 | Run BEAM at full 100K/500K/1M with Kendall τ before quoting any BEAM number, and state avg-score vs pass-rate | rewire currently has no publishable BEAM figure | Engineering plus an LLM budget |

The optional extras raise credibility further. One is an adapter for a neutral harness such as Supermemory MemoryBench, so rewire runs on the same pipeline as Mem0 and Zep ([memorybench](https://github.com/supermemoryai/memorybench)). Another is a judge sanity check that feeds deliberately wrong answers to the Haiku judge, the test that exposed the Mem0 prompt's leniency. A third is judge-human agreement on 100–200 hand-labelled items, plus a small memory-poisoning test to back up the security claims. Separately from scores, the release checklist should publish to PyPI and crates.io under one version number, remove the Indonesian README examples, add a CHANGELOG, and finish E1/E4 or state plainly that they are pending.

## Conclusion

The question "is rewire's J better than Mem0's or Zep's?" cannot be answered with today's evidence, and the wider field mostly cannot answer it for itself either. Once a shared harness reruns the self-reported 90%+ scores, they fall apart. rewire's real advantage lies elsewhere, and it is measurable now. It reaches the same accuracy band as the leading systems with **no LLM calls at ingest or recall by default**, **5–9k tokens of context**, and **millisecond retrieval** from plain markdown in git. That is a position on cost and portability, and it can be stated honestly without winning any leaderboard.

The right release is therefore a two-step one. Ship the alpha now, with benchmark results presented as internal engineering measurements that carry their model and judge labels. Hold any comparative claim until the gpt-4o-mini / GPT-4o-judge rerun and a same-model full-context baseline exist. Those two runs cost a few dollars, and they turn rewire's numbers from unverifiable into checkable. Shipping comparative scores first would repeat the mistakes that hurt Mem0, Zep and MemPalace.
