## Q1. What is CortexDB (product, company, license, open/closed, hosted/self-hostable)?

### Takeaway
CortexDB is a separate company's commercial "long-term memory layer for AI agents" (cortexdb.ai). It is credited to Prashant Malik, co-creator of Apache Cassandra. It ships as a managed cloud API (`api-v1.cortexdb.ai`) and as a public Docker image (`cortexdb/cortexdb`) labelled Apache-2.0. TinyHumans (OpenHuman) is a customer and integrator, not the vendor: it runs a hosted CortexDB behind its own backend and also lets users point at their own CortexDB. No public server source repository was found.

### Cited Findings
- CortexDB is marketed as "The Long-Term Memory Layer for AI Agents". Per the site, the "storage engine [was] built by Prashant Malik, co-creator of Apache Cassandra", and deployment is described as "Raft-replicated RocksDB, on-prem or in your cloud" / "Deploy on-prem or on our cloud" — [cortexdb.ai](https://cortexdb.ai/) (search snippet; page not fetchable from this session)
- Launch post dated 2026-04-03 by Malik, which mentions a planned "Managed cloud (Pro tier)" — [Introducing CortexDB](https://cortexdb.ai/blog/launch) (search snippet)
- Docker Hub `cortexdb/cortexdb`: public, registered 2026-05-20, 8,808 pulls. Tags include v0.9.13 (2026-09-18), v0.10.1–v0.10.5 (2026-09-28 to 2026-10-07) and v0.11.0 / latest (2026-10-08). Releases are frequent and the version is pre-1.0 — [Docker Hub API](https://hub.docker.com/v2/repositories/cortexdb/cortexdb/) (read directly)
- The v0.11.0 image config has the OCI labels `org.opencontainers.image.licenses: Apache-2.0`, title "CortexDB", "Long-term memory platform for AI agents" and documentation `https://cortexdb.ai/docs`. The v1 local engine (TinyCortex) is only a migration source now — [features/memory.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/memory.md)

### Inferences

- Pre-1.0 versions with roughly weekly releases (and a `io.cortexdb.one-way-below=0.11.0` label, which suggests one-way data migrations) mean the server is young and moving fast.

- Company legal entity, funding and team size: not found.
- Whether TinyHumans' hosted engine runs on cortexdb.ai's cloud or on TinyHumans' own CortexDB deployment. The docs say "Hosted CortexDB run by TinyHumans", which suggests their own deployment, but this is not confirmed.

## Q2. Data model and pipeline (events → facts → beliefs, extraction, belief building, conflicts, retrieval, vectors, graph/temporal)

### Takeaway
CortexDB is an append-only event log with derived layers: Events → Episodes → Facts (superseding triples) → Beliefs (confidence-scored, revisable) → Understanding. It has a bi-temporal model (valid time and recorded time) and an entity graph. Hybrid retrieval adds HyDE, a multi-hop query planner, salience routing, an optional Cohere rerank, and an LLM "verifier" lane. LLMs do the extraction ("enrichment") asynchronously. Belief builds run automatically on the managed API. OpenHuman additionally triggers them every 10 turns, on the direct engine only. Embedding model and dimensionality are configurable. The image defaults to OpenAI `text-embedding-3-small` at 1536-d. The 3072-d figure is TinyMemory's harness setting (`text-embedding-3-large`).

### Cited Findings
- **Layers:** Events (immutable log entries), Episodes (bounded spans of related events), Facts (triple-shaped, supersedable assertions), Beliefs (confidence-scored claims that are revised) and Understanding (a versioned conceptual model). Provenance: Beliefs cite Facts, Facts cite Episodes/Events, and Understanding cites everything — [cortexdb.ai docs: concepts/layers](https://cortexdb.ai/docs/concepts/layers) (search snippet)
- **Bi-temporal:** validity time (when a claim holds) and recorded time (when CortexDB learned it). New evidence supersedes and closes validity without deleting from the log. Derived records carry four time fields. Reads accept `as_of`, `valid_during`, `recorded_during` and natural-language temporal qualifiers — [concepts/bi-temporal](https://www.cortexdb.ai/docs/concepts/bi-temporal); [API_REFERENCE_V1](https://api.cortexdb.ai/docs/API_REFERENCE_V1.md) (search snippets; the API design doc is marked "Draft for review")
- **Bi-temporal enforcement is off by default:** `CORTEX_BITEMPORAL_MODE` defaults to `shadow`, with `enforce` and `off` as alternatives. `off` makes `v1/conflicts` return 503 — [tinymemory docs/evals/cortex-flags.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/cortex-flags.md)
- **Server feature flags** (checked by TinyMemory against the v0.10.4 binary): `CORTEX_ENTITY_GRAPH` (graph retrieval), `CORTEX_V1_LAYERS_AUTO` (auto-built belief layers), `CORTEX_AUTO_ROUTE` (per-question salience routing), `CORTEX_HYDE_PASSAGES_MS`, `CORTEX_MULTIHOP_QUERY_PLANNER_DISABLE`, `CORTEX_SALIENCE_WEIGHT` (default 0.10), `CORTEX_CONSOLIDATION_MAX_SURPRISE` (default 0.5), `CORTEX_POLARITY_RECHECK`, `CORTEX_V1_LAYERS_INCREMENTAL`, a verifier lane, `CORTEX_ENRICHMENT_SCOPE_QUIET_MS` and an optional Cohere `rerank-v3.5` cross-encoder. Background scheduler jobs include compaction (300 s), "methylation" (600 s), cognitive-persist (60 s) and feedback-weight (120 s) — [cortex-flags.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/cortex-flags.md); [integration/cortexdb/cortex.toml, flags/](https://github.com/tinyhumansai/tinymemory/tree/main/integration/cortexdb)
- **Storage / index config** (harness `cortex.toml`): RocksDB-style `data_path` with `wal_sync`, an HNSW vector index (`hnsw_m=32`, `ef_construction=500`, `ef_search=200`, quantization configurable, fp32 here), a 512 MiB block cache and `[cluster] node_id` — [integration/cortexdb/cortex.toml](https://github.com/tinyhumansai/tinymemory/blob/main/integration/cortexdb/cortex.toml)
- **Models are external, OpenAI-compatible lanes:** embedding, LLM/entity extraction, enrichment, answer and verifier each get their own URL, key and model. The image defaults are `CORTEX_LLM_MODEL=gpt-4o-mini`, `CORTEX_EMBEDDING_MODEL=text-embedding-3-small`, `CORTEX_EMBEDDING_DIMS=1536`, all pointing at `api.openai.com` — [cortexdb/cortexdb:v0.11.0 image config](https://hub.docker.com/r/cortexdb/cortexdb) (read directly); [docker-compose.yml](https://github.com/tinyhumansai/tinymemory/blob/main/integration/cortexdb/docker-compose.yml)
- **3072-d:** TinyMemory's harness sets `CORTEX_EMBEDDING_DIMS: "3072"` and `vector_dimensions = 3072`, and its real-model eval used `openai/text-embedding-3-large` through OpenRouter — [docker-compose.yml](https://github.com/tinyhumansai/tinymemory/blob/main/integration/cortexdb/docker-compose.yml); [docs/evals/agent-memory.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/agent-memory.md)
- **Verifier quirk (v0.10.4):** the docs say an empty `CORTEX_VERIFIER_URL` disables the verifier, but the server falls back to `api.openai.com` and enables it whenever `OPENAI_API_KEY` or `CORTEX_VERIFIER_API_KEY` is set — [cortex-flags.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/cortex-flags.md)
- **Wire API (as used by TinyMemory):** `v1/experience` and `v1/experience/bulk` (append events, with a body `idempotency_key`), `v1/events` (list), `v1/recall` (build a pack), `v1/answer` (LLM answer with citations), `v1/forget`, `v1/scopes/list`, `v1/beliefs` and `v1/beliefs/build`, `v1/erasures`, `v1/tenant/purge`, `v1/conflicts`, `v1/admin/usage`, `v1/admin/health` and `v1/auth/whoami` — [docs/architecture/cortex-wire.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/architecture/cortex-wire.md); [cortex-flags.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/cortex-flags.md)
- **Recall packs:** a cross-layer `budgets.max_tokens` (default 4000) "funds `include`'s layers first, then facts > beliefs > episodes > understanding > events, so without it events are evicted first". `view` defaults to `holistic` (the scope, its ancestors and its descendants). TinyMemory forces `granular`. A parent-scope pack is "filled from its children in storage order" (flagged `parent_pack_unranked_sample`) — [cortex-wire.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/architecture/cortex-wire.md)
- **Temporal hints:** `refers_during` is boost-only (capability `refers_to_v1`). `natural` and `valid_during` filter by capture time — [cortex-wire.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/architecture/cortex-wire.md)
- **Belief building:** v0.10 builds beliefs within the `v1/beliefs/build` request and returns `built`. A build takes seconds per scope (1.9–18 s per scenario in the eval). Automatic on the managed API (`api-v1.cortexdb.ai`), on demand elsewhere — [agent-memory.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/agent-memory.md); [tinymemory docs/integration.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/integration.md)
- **Every ~10 turns:** OpenHuman config `build_beliefs_every = 10` ("turns between belief builds; 0 turns them off") and `build_delay_secs = 300`. With the TinyHumans engine "beliefs are built on the service's own schedule"; the hosted backend exposes no build route — [openhuman memory.rs](https://github.com/tinyhumansai/openhuman/blob/main/crates/openhuman-core/src/config/schema/memory.rs); [features/memory.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/memory.md); [tinymemory docs/specs/agent-memory.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/specs/agent-memory.md)
- **Attribution (0.10.5):** events record `observed_actor` and `subject` — [cortex.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/architecture/cortex.md)
- Vendor whitepaper claim: disabling the Facts layer costs 22 points on LongMemEval-S — [architecture whitepaper](https://www.cortexdb.ai/docs/research/architecture-whitepaper) (search snippet, vendor claim)

### Inferences
- Conflict handling exists as machinery (bi-temporal supersession, a `v1/conflicts` route, polarity recheck), but in the default `shadow` mode it raised no conflicts in TinyMemory's eval (Q4). In practice contradictions are resolved by the reading LLM from the dates, not by the store.
- Every derived layer costs LLM calls on the server side. Quality and cost depend heavily on which models the operator wires in, so published scores are tied to a specific model configuration.

### Gaps
- The exact extraction prompts, ranking formula (how hybrid, graph, salience and recency are fused) and conflict-detection algorithm: server internals, not documented in the sources I could reach.
- Which embedding model and dimension the managed cloud and the TinyHumans hosted service use.

## Q3. What runs client-side in OpenHuman (TinyMemory) vs server-side?

### Takeaway
Client-side (open, GPL-3.0 TinyMemory and OpenHuman core): turn logging, secret and PII scrubbing, a local outbox, the scoping and namespace tree, the per-turn "memory pack" assembly (1,200 tokens over sections), merging per-scope results, date-prefixing bullets, re-lifting date-hint boosts after the merge, scheduling belief builds, and timeouts and fallbacks. Server-side (CortexDB): storage, embeddings, extraction/enrichment, facts and beliefs, ranking, graph/HyDE/multi-hop, answer synthesis, conflicts and erasure.

### Cited Findings
- OpenHuman `[memory.recall]` defaults: `budget_tokens = 1200`, `learnings_limit = 8`, `brain_limit = 6`, `history_limit = 6`, `team_limit = 3`, `build_beliefs_every = 10`, `pre_turn_timeout_ms = 10000`, `date_hint = false` ("a model call works out which days a turn is about"), `compaction_timeout_ms = 8000` — [openhuman memory.rs](https://github.com/tinyhumansai/openhuman/blob/main/crates/openhuman-core/src/config/schema/memory.rs)
- The pack is taken from "its short-lived cache, when one is available" and refreshed in the background. "The first turn can have no pack"; it is injected for that turn only and never written into the chat — [features/memory.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/memory.md)
- Client fixes: conversation bullets get a `[YYYY-MM-DD HH:MM]` prefix (`recall/gather.rs`), which made the model answer 6/6 contradiction probes with the current value. Up to 4 scopes are fetched concurrently (pre_turn p50 916 → 466 ms). Beliefs are folded into the Learnings section — [agent-memory.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/agent-memory.md)
- Date hints are boost-only. "The merged hits are lifted by day again, since the rank-by-rank scope merge would bury the server's boost" (`engine/refers.rs`) — [cortex-wire.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/architecture/cortex-wire.md)
- "Everything is scrubbed for secrets and personal identifiers before it leaves your machine". Tool calls are stored by name and id with a one-line result, never with their arguments — [features/memory.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/memory.md)
- Local state: "scrubbed agent `learn`/`forget` requests await delivery in a private outbox under `<workspace>/memory/`, alongside job queues and sync, backfill and import progress". Committed items are "never in a database on your machine" — [privacy-and-security.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/privacy-and-security.md)
- TinyMemory's `CortexEngine` "exposes no tuning: nearly every knob CortexDB has is a server environment variable". Fetch supports only `Hybrid` mode — [cortex-flags.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/cortex-flags.md); [cortex.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/architecture/cortex.md)
- The contract crate ships an in-memory `ReferenceEngine` (keyword plus 64-dim toy vector) for conformance tests only — [agent-memory.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/agent-memory.md); [docs/architecture/testing.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/architecture/testing.md)

### Inferences
- The open client is a thin orchestration and budgeting layer. Retrieval quality is decided by the server, and the client cannot tune it.

### Gaps
- None material. The client code was read directly at current HEAD.

## Q4. Benchmarks and claims (LoCoMo, LongMemEval, conflicts, latency, cost)

### Takeaway
Vendor-published scores are inconsistent across CortexDB's own pages (LoCoMo 76.4% / 85.5% / 86.9%; LongMemEval-S 93.8%), and I found no independent verification or third-party paper citing CortexDB. The only open, reproducible numbers come from TinyMemory's small agent-memory eval (38–52 probes, one run, 2026-10-04, CortexDB v0.10.4): 95–96% pack hit, 87–92% model answers, **0% of planted conflicts flagged**, belief building +0 pp, **enrichment (fact extraction) 67% of CortexDB model cost**, pre_turn p50 0.47–1.1 s. The "79.8% LoCoMo multi-hop J" figure was not found in any source.

### Cited Findings
- **Vendor LoCoMo/LongMemEval:** the V1 launch post claims 93.8% LongMemEval-S and 86.9% LoCoMo. The docs give 93.8% LongMemEval-S and 85.5% LoCoMo (categories 1–4, default config). The homepage lists 76.4% LoCoMo with an LLM judge. A May 2026 roadmap post says Mem0 leads at 91.6% against CortexDB's 86.9% — [Blog/V1 Launch](https://cortexdb.ai/blog/v1); [What's next](https://cortexdb.ai/blog/whats-next-for-cortexdb); [Getting Started](https://api.cortexdb.ai/docs/GETTING_STARTED.md); [cortexdb.ai](https://cortexdb.ai/) (all search snippets; the judge and answer models and per-category breakdowns were not visible)
- **No independent verification:** searches of arXiv and benchmark write-ups returned no paper or leaderboard that evaluates CortexDB — [search results, e.g. Mem0 "How to Read Memory Benchmarks"](https://mem0.ai/library/agent-memory/how-to-read-memory-benchmarks)
- **79.8% multi-hop:** not found on cortexdb.ai (per search), in the OpenHuman repo or in TinyMemory. The only 79.8% match in the OpenHuman tree is an unrelated HTML-compression benchmark. rewire's own analysis (`experiments/eval/results/2026-10-14-locomo-nemotron-s20-analysis.md` §9) attributes it to "CortexDB/OpenHuman … a vendor claim" without a link — [openhuman vendor/tinyjuice/docs/benchmark/html-status-report/README.md](https://github.com/tinyhumansai/openhuman) (grep result)
- **TinyMemory agent-memory eval** (2026-10-04, v0.10.4, `text-embedding-3-large` + `gpt-4.1-mini` via OpenRouter, 38 probes): pack holds the answer 95% (97% after synthesis), model answer 92% (95%), paraphrase pack hit 92%, contradictions answered with the current value 6/6 (after adding dates), cross-tenant leaks 0/3, but "fresh first" only 1/5 → 2/5. "Retrieval puts the superseded value first in 4 of 5 contradiction probes." CortexDB built 281 beliefs, but they "never show" in fetched sections (since fixed client-side; the real-model rerun is pending because "the OpenRouter workspace budget ran out") — [agent-memory.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/agent-memory.md)
- **TinyMemory flags eval, real-model baseline** (one run, 52 probes): pack hit 96%/96%, model answer 87%, captured as fact or belief 100%, lessons answered 71%, **synthesis gain +0 pp**, 160 beliefs held (mean confidence 0.99, 1 not supported), **planted conflicts flagged 0% (0 conflicts raised anywhere)** under the default `shadow` mode, disagreement in pack 100%, fresh first 57% — [cortex-flags.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/cortex-flags.md)
- **Cost:** CortexDB models cost $0.43 (1,577 calls, 1.39M tokens) for the run; "enrichment (fact extraction) is $0.29 (67%), belief building $0.07, fact maintenance $0.03, and embeddings, recall and answers about $0.01–0.02 each". Answerer $0.02, $0.010 per correct answer. A full 16-profile × 2 sweep was estimated at about $16. In the v3 host eval the CortexDB model cost was about $0.02 per small slice — [cortex-flags.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/cortex-flags.md); [openhuman-host.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/openhuman-host.md)
- **Latency** (real models): `post_turn` p50 2.4 ms (it does not wait for indexing). `pre_turn` p50 466 ms, p95 1,168 ms (one query embedding per scope, the provider round trip). Probe pre_turn p95 2,081 ms, max 5.1 s. `recall_for_compaction` (an LLM answer) about 2 s. A brain ingest takes 1.9–2.9 s to become visible. In the flags baseline pre_turn p50 was 1.1 s and p95 1.5 s. With mock models pre_turn is 13 ms p50 — [agent-memory.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/agent-memory.md); [cortex-flags.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/cortex-flags.md)
- Caveats stated by the authors: "The sample is small… one probe is about 2 points". Mock models "measure plumbing, not intelligence". Graph, multihop and HyDE "are tuned for … thousands of events", while each scenario holds a few dozen — [cortex-flags.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/cortex-flags.md)

### Inferences
- TinyMemory's eval is the most credible public evidence, since it is reproducible with a public image and harness. But it was written by an integrator, not an independent party, and it is smoke-sized: no LoCoMo or LongMemEval run of CortexDB exists in the open repos.
- The 67% extraction share is a per-run measurement with `gpt-4.1-mini`. It shows that per-turn ingest cost is dominated by LLM extraction on the server, the opposite of a design with no LLM at query time.
- rewire's "79.8% multi-hop J" comparison target should be treated as unsourced until a link is found.

### Gaps
- Vendor benchmark methodology: judge model, answer model, top-k and which LoCoMo categories. The pages were unreachable.
- Any independent LoCoMo or LongMemEval run of CortexDB.
- Per-message cost on the managed or hosted services, as opposed to self-hosted model spend.

## Q5. Operational properties (network, privacy/residency, offline, pricing, rate limits, lock-in, export)

### Takeaway
OpenHuman memory needs the network unless the user self-hosts CortexDB, and even then CortexDB needs model endpoints for embeddings and extraction (any OpenAI-compatible server). Hosted memory is readable by the operator: TLS in transit only, with no E2E or client-side encryption. Managed pricing per search snippets: a free tier (10K memories, 1K recalls a month, 1 tenant, 7-day anonymous tokens), Starter $348/yr, Pro $1,788/yr (1M memories, 150K recalls a month, 20 tenants, 99.9% SLA). Export is limited: memory does not move with a folder copy, and OpenHuman removed engine migration.

### Cited Findings
- "Your workspace files, settings and audio buffers stay on your machine. Your memory does not." "We claim only TLS in transit and per-user tenant isolation for hosted memory… The hosted service can read what it stores" — [privacy-and-security.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/privacy-and-security.md)
- Local-only (privacy) mode allows "Memory on a CortexDB endpoint you run yourself. The hosted TinyHumans engine is a cloud call, so local-only mode blocks it" — [features/privacy-mode.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/privacy-mode.md)
- With no sign-in and no CortexDB key, "memory is off. The agent has no memory tool, nothing is stored" — [features/memory.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/memory.md)
- Self-hosting: the public image runs locally (TinyMemory's harness boots `cortexdb/cortexdb:v0.10.4` on 127.0.0.1:3141 with a static bearer and `CORTEX_DEPLOYMENT_PRESET=dev_local`). It needs embedding, LLM, enrichment, answer and verifier endpoints, and TinyMemory substitutes a deterministic mock for tests — [integration/cortexdb/README.md, docker-compose.yml](https://github.com/tinyhumansai/tinymemory/tree/main/integration/cortexdb)
- Client failure handling: a 402 on hosted means `USER_INSUFFICIENT_CREDITS`, and the host shows a top-up prompt. A 429 is honoured via `Retry-After` (capped at 10 s). Writes are sent once. Reads retry 3× (250/500 ms). Request timeout is 60 s. The OpenHuman pre-turn deadline is 10 s, after which the pack is empty — [cortex.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/architecture/cortex.md); [openhuman-host.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/evals/openhuman-host.md)
- Hosted: "The backend applies a per-user rate limit and billing" — [privacy-and-security.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/privacy-and-security.md)
- Pricing (managed cortexdb.ai): free tier "No credit card required" with 10K memories, 1K recall calls a month and 1 tenant; Starter $348/yr; Pro $1,788/yr with 1M memories, 150K recalls a month, 20 tenants and a 99.9% SLA. Free tokens come from anonymous signup with a 7-day TTL. Requests need an `X-Cortex-Actor` header — [cortexdb.ai/pricing](https://www.cortexdb.ai/pricing); [docs/sdks/rest-api](https://www.cortexdb.ai/docs/sdks/rest-api) (search snippets, unverified)
- Moving machines: "Memory items | In your engine (TinyHumans or CortexDB) | No [does not travel with a folder copy]. Sign in again or re-enter the key" — [guides/move-to-new-pc.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/guides/move-to-new-pc.md)
- Lock-in and export: "Other memory engines … are gone, and so is migrating between engines". The scope listing caps at 1,000 paths, beyond which "an export refuses". Erase-all is supported (hosted `DELETE /memory`; direct erasure per `org:<id>` tree) — [features/memory.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/memory.md); [cortex-wire.md](https://github.com/tinyhumansai/tinymemory/blob/main/docs/architecture/cortex-wire.md); [privacy-and-security.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/privacy-and-security.md)
- Explicit memory writes are asynchronous: a `learn` acknowledgement means "queued; not yet saved to memory" — [features/memory.md](https://github.com/tinyhumansai/openhuman/blob/main/docs/gitbooks/en/features/memory.md)

### Inferences
- Compared with a markdown-in-git store with a derived SQLite index, CortexDB is not offline-capable in OpenHuman's default configuration. It is not human-readable or diffable at rest (a RocksDB-style data dir behind an HTTP API). Its history lives in the server's event log rather than in git. Portability depends on the API (list events per scope) rather than on files.
- The cost model is per-write LLM extraction plus per-read embedding round trips. A local index with no LLM at query time avoids both.

### Gaps
- TinyHumans' own pricing for hosted memory (credits per write or recall): not found.
- Data residency (regions) for cortexdb.ai cloud or for TinyHumans: not found.
- A documented bulk export or backup format for CortexDB: not found. Only per-scope event listing via the API was confirmed.
